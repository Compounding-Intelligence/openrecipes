Notes for Muse-Spark-Open-816B-A42B

  • Weights: the BF16 checkpoint meta-models/Muse-Spark-Open-816B-A42B (revision 0fb02478), converted to Megatron torch_dist with miles' tools/convert_hf_to_torch_dist.py at commit bfdcff0e. --hf-checkpoint is the full checkout, whose config.json miles' Muse Spark model provider reads; the recipes train the text model only.
  • MODEL_ARGS come from miles' scripts/models/muse-spark-full.py (radixark/miles PR #4111, commit bfdcff0e), printed by miles/utils/external_utils/model_args_utils.py muse-spark-full; run the command from a miles checkout at that commit.
  • It trains on its own rows, built with --loss-mask-type muse_spark (data/README.md).
  • Train-only runs pass --debug-skip-weight-update. Without it, miles' sample weight-version check (miles/utils/weight_version.py) reads an SGLang argument that --debug-train-only leaves unset, and the run stops before step 0.
  • The published radixark/miles:muse-spark-open image ships Transformer Engine's PyTorch extension and flash-attn 2 compiled against an older PyTorch than its 2.14.1, and both fail to import (undefined c10_cuda_check_implementation). Rebuild them against the installed PyTorch for the GPUs you train on (sm90 for H200, sm100 for B200): TE 2.17.0 from its PyPI sdist and flash-attn 2.7.4.post1 from source, with -std=c++20 as the PyTorch 2.14 headers require.
  • On B200, use --attention-backend fused (cuDNN fused attention). With flash, TE 2.17 selects FlashAttention 4 (flash-attn-4 4.0.0b19 in the image; FlashAttention 3 is Hopper-only), whose sm100 forward calls quack.activation.sub_packed_f32x2; the image's quack-kernels 0.6.5 lacks it, and the run stops at step 0. auto reaches FlashAttention 4 too wherever TE prefers it.
  • With the EFA plugin installed, set EP_SUPPRESS_NCCL_CHECK=1: DeepEP's import-time check counts every loaded libnccl* file, takes the plugin's libraries for a second NCCL runtime and stops the process.

  • Starting point: the layout of miles' Muse Spark launcher for 64 H200, scripts/run_muse_spark_64xh200.py (https://github.com/radixark/miles/pull/4111; model page https://miles.radixark.com/docs/models/muse-spark/muse-spark-open), which miles lists as untested on B200 and publishes with step times and no tokens/s figure. Ported to this workload on 128 B200 with that layout (TP 8, PP 8 with 7 layers on the first and last stages), EP 16 and Adam on the GPU, it measured 343.3 tokens/s/GPU; ATTUNE tuned it to 505.2 (+47%).
  • Adam stays on the GPU: the measured run peaked at 157.8 GiB used per GPU of 178.35 GiB. EP 8 is the smallest EP that fits at PP 16: a tuning run at EP 4 ran out of memory at step 0.
