Notes for Inkling-Small

  • Weights: the BF16 checkpoint thinkingmachines/Inkling-Small (revision 8cc5877b), converted to Megatron torch_dist with miles' tools/convert_hf_to_torch_dist.py at commit 78527b91 and the inkling-small model arguments on one 8-GPU node (TP 8, EP 8), as miles' model page describes. --ref-load is the conversion and --hf-checkpoint the checkout, whose config.json miles' Inkling model reads.
  • MODEL_ARGS come from miles' scripts/models/inkling-small.py at commit 78527b91, printed by miles/utils/external_utils/model_args_utils.py inkling-small; run the command from a miles checkout at that commit. They select miles' text model provider (miles_plugins.models.inkling.model.inkling_model_provider), so the recipes train the text model only.
  • It trains on its own rows, built with --loss-mask-type inkling (data/README.md).
  • --ref-load replaces the launcher's --load <torch_dist> --no-load-optim --no-load-rng --finetune: with a checkpoint tracker at --load, miles starts at rollout 1 and the run logs no step 0; --ref-load loads the same weights and starts at rollout 0 (miles/utils/arguments.py).
  • miles' Inkling model builds its own Megatron config (build_inkling_config in miles_plugins/models/inkling/model.py), which takes no recompute settings and fixes the token dispatcher to alltoall, so the --recompute-* flags the launcher passes have no effect.

#1attune-tp4-pp4-ep8-split12616.7 tokens/s/GPUTP4 PP4 EP8 DP212/10/10/10 layer split, CPU optimizer offload 0.7
  • Starting point: miles' Inkling launcher, scripts/run_inkling.py at miles 0.1.0, with its Inkling-Small profile (model page https://miles.radixark.com/docs/models/thinkingmachines/inkling-small). miles publishes it as a GRPO recipe validated on 4 nodes of 8 H200, with no tokens/s figure. Ported to this workload with that layout (TP 4 with sequence parallel, PP 8, EP 4, Adam on the CPU) on 32 H200, it measured 396.9 tokens/s/GPU; ATTUNE tuned it to 616.7 (+55%).
  • EP 8 places each expert group within one node. The first pipeline stage holds the two dense layers and ten MoE layers and peaks highest in memory; at --optimizer-offload-fraction 0.7, 30% of the optimizer state stays on the GPU, and a tuning run at 0.6 ran out of memory. Check the memory before lowering the fraction.

  --actor-num-gpus-per-node 8 \

  --ref-load "$TORCH_DIST" \
  --model-name inkling \
  --megatron-to-hf-mode raw \
  --loss-type sft_loss \
  --calculate-per-token-loss \
  --disable-compute-advantages-and-returns \
  --debug-train-only \
  --rollout-function-path pretokenized_sft_rollout.generate_rollout \
  --prompt-data "$SFT_DATA" \
  --input-key messages \
  --metadata-key metadata \
  --num-rollout 20 \
  --rollout-batch-size 128 \
  --global-batch-size 128 \
  --tensor-model-parallel-size 4 \
  --sequence-parallel \
  --pipeline-model-parallel-size 4 \
  --decoder-first-pipeline-num-layers 12 \
  --expert-model-parallel-size 8 \
  --expert-tensor-parallel-size 1 \
  --recompute-granularity full \
  --recompute-method uniform \
  --recompute-num-layers 1 \
  --micro-batch-size 1 \

  --lr-warmup-fraction 0.1 --weight-decay 0.1 --adam-beta1 0.9 --adam-beta2 0.98 \
  --use-distributed-optimizer \
  --no-check-for-nan-in-loss-and-grad \
  --accumulate-allreduce-grads-in-fp32 \
  --optimizer-cpu-offload --overlap-cpu-optimizer-d2h-h2d --use-precision-aware-optimizer \
  --optimizer-offload-fraction 0.7 \
  --transformer-impl transformer_engine \
  --bf16 \
  --attention-dropout 0.0 --hidden-dropout 0.0 \
  --attention-softmax-in-fp32 \
  --no-bias-dropout-fusion \
  --distributed-timeout-minutes 30
