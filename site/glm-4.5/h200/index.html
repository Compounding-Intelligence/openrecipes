Notes for GLM-4.5

  • Weights: the BF16 checkpoint zai-org/GLM-4.5 (revision cbb2c7cf), converted to Megatron torch_dist with miles' tools/convert_hf_to_torch_dist.py at commit 78527b91 and the recipes' MODEL_ARGS on one 8-GPU node. The model arguments build no multi-token-prediction layer, so the checkpoint's layer 92 is neither converted nor trained. --ref-load is the conversion and --hf-checkpoint the checkout.
  • MODEL_ARGS come from miles' scripts/models/glm4.5-355B-A32B.py at commit 78527b91, printed by miles/utils/external_utils/model_args_utils.py glm4.5-355B-A32B; run the command from a miles checkout at that commit.
  • It trains on its own rows, built with --loss-mask-type glm45 (data/README.md).
  • The recipes run without --overlap-grad-reduce and --overlap-param-gather. With --overlap-grad-reduce, miles' train() (miles/backends/megatron_utils/model.py) asserts that config.no_sync_func is unset and then sets it; it runs once per rollout, so the second rollout fails the assertion.

Recipes

#1attune-tp4-pp16-ep8565.4 tokens/s/GPUTP4 PP16 EP8 DP2PP 16, no recompute
  • Starting point: Megatron-Bridge's GLM-4.5 pretraining recipe for 128 x H100 (TP 2 with sequence parallel, PP 8, EP 16), the reference recipe above. Megatron-Bridge has no H200 recipe for GLM-4.5, and miles' GLM-4.5 launchers are GRPO and GSPO scripts that colocate their rollout engines on the training GPUs and publish no tokens/s figure. Ported to this workload on 128 H200, the Megatron-Bridge recipe measured 224.8 tokens/s/GPU in the campaign's baseline run and 297.7 in an earlier run of the same configuration on other nodes; ATTUNE tuned it to 565.4 (+152% over the baseline run, +90% over the earlier run). A 23-step run of this recipe on other nodes, profiled on its last step, measured 564.9 over steps 5-19.
  • Each pipeline stage holds one node's 8 GPUs (TP 4 x DP 2), so the tensor-, expert- and data-parallel traffic stays inside the node and only the pipeline crosses nodes. The extra stages leave room to drop recompute: the ranks the measured run's log shows peak at about 103 GB reserved of 140, and interleaving (VPP 2) without recompute ran out of memory at step 1.
  • --moe-aux-loss-coeff 1e-3 after MODEL_ARGS keeps the reference recipe's sequence auxiliary-loss coefficient; miles' GLM-4.5 model arguments set it to 0.
